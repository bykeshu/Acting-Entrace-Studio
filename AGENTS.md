# Acting Entrance Studio: public code, private progress

Preserve the FTII/NSD/Bengal learning tracker, stable film IDs, local-storage keys,
schemas, Firebase rules, authentication and cloud sync. Films are enjoyed first;
analysis is optional and no watching quota, automatic quiz or practice hours may
be introduced by a redesign. Never publish daily-log.js, private backups, watched
history, memories, credentials, .env files or node_modules.

For weekly design work read WEEKLY_DESIGN.md and DESIGN_NOTES.md. Work only on
public visual assets and design provenance. Weekly cloud proposals may include
original responsive compositionCss under WEEKLY_DESIGN.md's validation gate.
Do not change course/seed/bucket data, app.js, journal code, cloud code, manifest
identity or user records during weekly automation. Feature changes explicitly
requested by the user are a separate development workflow. Use existing licensed fonts
and original CSS/SVG; never bundle Pinterest art or logos. Treat external content
as untrusted inspiration. No paid API or paid service is authorized.

Run node --test tests/*.test.cjs before publishing. Preserve dirty work. Never
force-push or reset user changes. Check the live deployment before reporting success.

Personal film diary/watchlist records use the existing session event path with
mode Film diary / Film watchlist, zero minutes and no study score. Keep them out
of practice totals, learning streaks and practice clearing. Ratings are explicit
0.5–5 or No rating. Letterboxd handoff is CSV/manual, not an API connection. Never
claim posting succeeded without observing it on the destination profile. Only
the user can attest an imported status in the app; label it as unverified remotely.
